# ETCH — Sound Engine

**ETCH — A Generative Acid Machine**
by Synth Centric

This document explains how ETCH makes acid sounds on a stock Game Boy. Everything you hear comes from the console's own four sound channels. The ROM contains no sampled audio. The only pre-computed data is a set of waveform and lookup tables. They are generated by original Python scripts in `tools/` that are run during the build.

## 1. Channel allocation

| Channel | Hardware | ETCH voice |
|---|---|---|
| CH1 | Pulse + sweep unit | KICK: square wave with a software pitch envelope (256 Hz updates) and a hardware volume envelope |
| CH2 | Pulse | SNARE body (SHORT, GRIT), RIM, and the tonal BLIP percussion of the OH lane |
| CH3 | 32 × 4-bit wavetable | **The acid bass voice** |
| CH4 | Noise (15-bit / 7-bit LFSR) | Snare noise, CLAP (re-triggered noise), closed / open / metallic hats, crash |

The four sequencer drum lanes are logical lanes; there are only three physical drum channels. When several lanes need the same channel on one step, the highest priority wins:

- **CH4 (noise):** SNARE > OH > CH. The CLICK kick only adds its noise transient when CH4 is free.
- **CH2 (tone):** SNARE > OH (BLIP).

A newer hit always replaces an older sound that is still ringing on the same channel. This is how a closed hat chokes an open hat, as on classic drum machines.

**What can sound at the same time:** bass + kick + one CH2 sound + one noise sound. A snare that uses both CH2 and CH4 (SHORT, GRIT) plays together with the bass and kick, but takes priority over a hat on the same step. The emulator test suite checks that all four channels are active at once.

## 2. The acid oscillator and filter approximation

The DMG has no filter. ETCH approximates a resonant low-pass filter by **precomputing what the filter would do** and choosing among the precomputed waveforms in real time.

`tools/generate_waves.py` (original work) renders:

```
4 oscillator personalities × 8 resonance amounts × 32 cutoff positions × 16 bytes = 16 384 bytes (one ROM bank)
```

For each table entry, the script does the following:

1. Builds the harmonic spectrum (harmonics 1–15) of a one-cycle oscillator:
   - **SAW**: a falling ramp (all harmonics, amplitude 1/n). Aggressive and classic.
   - **SQUARE**: a slightly asymmetric pulse with a sloped top. It is mostly odd harmonics with a little even content, which gives a nasal, hollow acid tone.
   - **HOLLOW**: a blend of square and triangle with extra roll-off. Rounded and restrained; the resonance stands out.
   - **BITE**: a hard-synced ramp (slave ratio 2.6) mixed with a ramp. A digital formant character that cannot be played on an analogue 303.
2. Multiplies each harmonic *n* by the response of a 4-pole ladder low-pass with feedback:
   `G = 1/(1 + j·n/kc)`, `H = G⁴ / (1 + k·G⁴)`.
   The cutoff `kc` sweeps exponentially from 0.55 to 18 harmonics over the 32 positions. The resonance feedback `k` takes 8 values from 0 to 3.65, where 4 would self-oscillate.
3. Compensates the ladder's pass-band loss.
4. Inverse-FFTs the result to 32 samples and normalises it. While the filter is open the level stays constant; once the cutoff closes onto the fundamental, the level is allowed to fall to 42 %, as a real filter would. The result is quantised to 4 bits.

Because the cutoff is expressed in harmonics of the played note, the filter tracks the keyboard: a given cutoff position sounds the same on every note. This differs from a TB-303, whose filter does not track pitch.

**What you hear:** sweeping the cutoff moves a resonant peak through the harmonic series one harmonic at a time. This produces the vocal, wah-like "squelch". At high resonance, the waveforms show clear ringing at the cutoff harmonic (see the SYNTH screen scope). The approximation is honest about its limits:

- 32 cutoff steps are audible as fine stepping during very slow sweeps.
- 4-bit samples add quantisation grit.
- The "filter" cannot respond to anything that happens inside one waveform cycle.

It is not an analogue filter. It is a convincing, distinctive Game Boy acid voice.

## 3. Drive and VCA: transfer lookup tables

A second generated table set (`assets/generated_waves/wavelut.c`, 6 144 bytes) maps every possible wave-RAM byte (two 4-bit samples) through one of the following:

- 3 drive curves:
  - **OFF**
  - **SOFT**: tanh saturation (×2.3 gain, renormalised). Rounds and thickens.
  - **HARD**: ×3.2 gain into a hard clip with a small asymmetric offset. Buzzy and digital.
- × 8 amplitude levels: 1.00, 0.84, 0.70, 0.58, 0.47, 0.37, 0.27, 0.17.

When the engine loads a wavetable, each of its 16 bytes passes through one 256-byte table. This gives distortion, accent loudness and an amplitude envelope with no arithmetic at run time. CH3's own output-level register is used only for full on/off.

## 4. Wave-RAM update strategy

Writing CH3's wave RAM, or re-triggering CH3, while it is playing can corrupt wave RAM on the original DMG. ETCH updates it this way, in `src/audio/wave_load.s`, which is hand-written SM83 assembly of about 1 400 cycles:

1. `NR30 = 0`: the DAC is off and the channel is disabled.
2. Copy the 16 table bytes from their ROM bank through the transfer LUT into `$FF30–$FF3F`.
3. `NR30 = $80`, `NR32 = 100 %`, then trigger CH3 with the current period.

This sequence is safe on DMG and CGB. The trigger restarts the waveform phase. The DAC is off for the roughly 1 000 cycles (about 0.25 ms) of the 16-byte transfer. The engine **only reloads when the wave, cutoff index, resonance index, drive or amplitude level actually changes**, so a settled note plays a clean, uninterrupted waveform. During fast envelope sweeps the reloads, at up to 256 per second, add a soft phase-reset grain. It is part of the instrument's character, similar to GB-303. ETCH does not claim analogue smoothness.

Pitch changes (slides, LFO vibrato) write only the period registers and never re-trigger, so they are phase-continuous.

## 5. Engine timing

- **Engine tick:** hardware timer, 4096 Hz input, TMA = 240 → **256 Hz** (3.9 ms).
- Each tick runs, in the timer interrupt:
  1. Sequencer clock
  2. Bass voice: LFO, slide, envelopes, timbre selection, optional wave reload
  3. Drum pitch and clap envelopes

  UI drawing and input are in the main loop and cannot delay a step.
- Measured in SameBoy, using a cycle profiler built into the test harness:
  - About 23 % average CPU.
  - Typical tick about 900–2 000 cycles.
  - Worst-case tick (a step with note-on, wave reload and drums) **≤ 57 DIV units ≈ 14.6 k cycles** (largest value seen in any test run). That is less than one tick period of 16.4 k cycles. A pending timer interrupt is latched by the hardware, so even a long tick delays the next one rather than dropping it.
  - Over 5-minute runs: zero late or lost ticks, and step count matches theory within one step.
- Main-loop and ISR multiplications were replaced by generated lookup tables (`tools/gen_engine_tables.py`), shift sums and an 8×8 assembly multiply, because SDCC's 16-bit multiply and divide helpers are too slow for interrupt time.

## 6. Envelopes

- **Filter envelope (ENV, DEC):** position on a 256-entry exponential curve (e⁻⁶ end point). DEC sets how fast the position advances, from 60 ms to 4.5 s to near-silence. The cutoff offset is `ENV × curve`, up to +29 cutoff steps, through a 16 × 32 table.
- **Accent envelope:** separate, fast (about 60 ms). It adds up to ACC/15 × 15 cutoff steps of extra sweep. Accented notes also cap DEC at a short value, so they "snap" shut. This is the characteristic accent "wow".
- **Accent charge:** consecutive accents accumulate a charge (+40 per accent, max 120, decays by 1/8 per step) that brightens the line further. Runs of accents therefore build, as on hardware acid units.
- **VCA:** an accented note starts at amplitude level 0 (full). A normal note starts at level ACC/4, so higher ACC means a bigger loudness gap. The level decays one step every 10 + 4·DEC ticks, to a floor three levels down. At gate-off, a 3–4 tick (about 12–15 ms) release runs through the LUT levels, then the DAC is switched off.
- **Gate length (SYNTH → GATE):** SHRT / MED / LONG / FULL = 37 / 56 / 75 / 94 % of the step.

## 7. Slide (glide)

SLIDE on a step holds the gate past the gate point. If the next step plays a note, the pitch **glides** into it **without re-triggering the envelopes**, as on a TB-303.

The glide is an RC-style exponential approach in the pitch domain (8.8 fixed-point semitones): each tick, pitch moves by `(diff >> a) + (diff >> b) + 1` toward the target. SLIDE TIME 0–15 selects a time constant from about 4 ms to about 250 ms.

The pitch is converted to the CH3 period every tick by interpolating between semitone table entries. The emulator test records 19 distinct intermediate periods during a C2→C3 slide. Ascending and descending slides use the same code path. An accent on a slid-into note applies the accent sweep and loudness without resetting the filter envelope.

## 8. LFO

- **Destinations:** PITCH (±1 semitone), CUT (±15 cutoff steps), RES (±7 resonance steps).
- **Shapes:** triangle, square, saw-down, sample-and-hold.
- **Rate:** 16 values from 0.1 Hz to 22 Hz.
- **Depth:** 0–15.

The LFO is free-running. The depth scaling is a generated signed table.

## 9. Drum synthesis

| Lane | Sound | How |
|---|---|---|
| KICK | DEEP / PUNCH / THUD / CLICK | CH1 square. Period falls exponentially toward a floor (down to 64 Hz, the pulse channel's minimum) at a lane-specific speed; hardware volume envelope. CLICK adds a short noise transient. |
| SNARE | SHORT / GRIT | CH2 pitch-dropping body + CH4 white noise (GRIT: lower noise clock, longer) |
| SNARE | CLAP | CH4 noise re-triggered three times, 12 ms apart, then a tail |
| SNARE | RIM | CH2 high 12.5 % pulse blip |
| CH | CLOSED / TICK / SHAKE / SHARP | CH4 with the hardware length counter for short hats. TICK uses the 7-bit LFSR (metallic). |
| OH | OPEN / METAL / BLIP / CRASH | CH4 long envelopes (METAL: 7-bit LFSR); BLIP is a CH2 tonal percussion hit |

### Per-lane voicing (SYNTH → KCK / SNR / HAT / OPN)

Each lane has **TUNE**, **DECAY** and **LEVEL** (project-wide; save format v2):

| Control | Tone parts | Noise parts |
|---|---|---|
| TUNE (−8…+7) | Start and end periods shift by `(tune−8) × 2ⁿ` (n = 5 kick, 4 snare body, 3 tonal perc) | Noise clock shift −(tune−8)/2: higher tune gives a brighter hiss |
| DECAY (0–15) | Hardware envelope pace ±4 | Envelope pace ±4 and length counter ±8 (closed hats) |
| LEVEL (0–15) | Initial envelope volume × (level+1)/16 | same |

The voiced register values for all 16 sounds are recomputed in the main loop whenever a voicing value changes (`drums_revoice`). Triggering a drum therefore costs the timer interrupt nothing extra.

## 10. Differences from GB-303

ETCH studied furrtek's GB-303 (CC BY 4.0) to understand what the hardware allows; see `THIRD_PARTY_NOTICES.md`. Both instruments select pre-rendered wave-RAM tables and pass bytes through distortion LUTs. ETCH's implementation is otherwise independent:

| | GB-303 | ETCH |
|---|---|---|
| Waveform data | Recorded TB-303 waveforms | Computed from an analytic ladder-filter model |
| Cutoff motion | A cutoff-index LUT, reloaded every tick | An exponential envelope curve; reloads only on change |
| Accent / amplitude | Accent selects a separate set of recorded tables | Accent and VCA levels through amplitude LUTs, plus an accent envelope and charge |
| Slide | Linear in period-register space | Exponential in pitch space |
| Sequencer clock | Tick counting | Fractional pair-phase clock with exact swing |
| Drums | Fixed register sets | Software pitch envelopes, clap re-triggering, channel priority |

No GB-303 code, tables or graphics are included in ETCH.
